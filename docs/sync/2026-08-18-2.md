## 坑: 浅取边界导致 fetch 报错

- 现象: `git fetch --depth=1` fatal `Could not read f2f6dce...`(多次间歇出现)
- 根因: **不是 subtree 相关**。`refs/remotes/upstream/main` tracking ref 停留在
  旧提交 `9ed4a7c`,其历史链深处一个更早的 parent(`f2f6dce`)在多次浅取后丢失;
  fetch 要更新该 ref 时遍历其链 → 撞缺失对象。
- 修复: `git update-ref -d refs/remotes/upstream/main`(陈旧 tracking ref),
  fetch 按需重建,fetch 恢复。
- 教训: 浅取 + tracking ref 长期不更新会累积缺失对象;同步前若 fetch 报
  `Could not read`,先删 `refs/remotes/upstream/main` 再试。
