## 桥面契约变化（global.d.ts）与处理

```diff
- getConnection(profile?, opts?: { priority })            → getConnection(profile?)
- getConnectionFor({ connectionId, profile, priority })     → 去掉 priority
- touchBackend / getPoolLimits / setPoolLimits              （必填面，整体删除）
- onPoolBackendRetiring?                                    （可选面，删除）
+ preparedSubmissions? { read, update, compareAndSet? }    （新增可选组）
```

| 上游变化                                             | 类型       | 本仓处理                                                                                                                                                                    |
| ---------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `touchBackend` / `getPoolLimits` / `setPoolLimits`   | 必填面删除 | 桥层同步删除（`adapter.ts` 三处、`gateway/index.ts` 的 `touchBackend()`、`index.test.ts` 断言）——`const bridge: Bridge = {…}` 是对象字面量，多出成员会 excess property 报错 |
| `onPoolBackendRetiring?`                             | 可选面删除 | 本仓本就未实现，无需处理                                                                                                                                                    |
| `preparedSubmissions?`                               | 可选组新增 | **不实现**：vendor `use-prompt-actions/prepared-submissions.ts` 是 `native ? native.read() : localStorage` 双路，浏览器已有 localStorage 日志（无 native 时的设计内路径）   |
| `getConnection` / `getConnectionFor` 去掉 `priority` | 签名收窄   | 桥层 `getConnectionFor` 参数类型同步删 `priority`（桥不消费该字段；`getConnection` 本就不传参）                                                                             |

机械比对成员集（解析 `declare global` 的 `hermesDesktop` 成员）：ADDED = `preparedSubmissions`，
REMOVED = 上述四个，组内成员与可选性无其它变化。桥面扫描：`adapter.ts` 顶层键 ⊆ `global.d.ts`
成员集合，**无多余成员、无缺失必填成员**（可选面按约定不实现，共 33 个）。
