## Web 桥面处理（新接口）

- **新增必填** `savePastedText(text) → Promise<string>`：大段纯文本粘贴转 `.txt`
  附件。桌面主进程写 `userData/composer-pastes/pasted_content_<stamp>_<rand>.txt`
  返回本地路径；浏览器无 gateway 侧路径但**有等价实现**（附件字节模型
  ADR-0020/0024）→ **已实现**：文本写 OPFS `web-blobs/`，返回虚拟路径
  `web-blob://attach/<id>/pasted_content_….txt`，渲染层随后走同一条 `@file:`
  附件链路（提交时 `readFileDataUrl` → data_url）。`browser.ts` 实现 + adapter
  接线 + 单测（browser.test.ts 两条、adapter.test.ts 表面一条）。
- **移除** `agentPluginsRoot?`（上游替换为可选 `reconcileDesktopPlugins?`）：
  `reconcileDesktopPlugins` = 把统一包的 desktop 半重拷到 app 级插件 root，
  Electron 主进程文件操作，浏览器无等价 → **不实现**（vendor 侧全部
  optional-chain，缺省即跳过）。`adapter.ts` / `denied.ts` 内的 `agentPluginsRoot`
  已删除（否则对象字面量对桥类型报多余属性）。
- **新增可选（不实现）**：`introReveal?`（品牌片 overlay 窗口）、`chatOnboarding?`
  （主窗口按边生长/收束）、`getMachineProfile?`（主机事实，仅首启默认值）、
  `guestOnboardingEnabled?` / `skipIntro?`（启动标志，直接读值；undefined 即
  「无引导片」，Web 语义正确）、`reconcileDesktopPlugins?`（见上）。
- **签名微调（兼容，无需改桥）**：`updates.check(opts?)` 增加可选参（denied 的
  0 参实现可赋值）；`DesktopConnectionConfigInput.cloudName?`、`HermesApiRequest.passive?`
  均为可选字段（`api()` 整包透传请求体，无需改）。
- **类型迁移**：`HermesNotification` 从 `global.d.ts` 迁到
  `vendor/hermes-desktop/electron/notification-types.ts`（electron 侧，在 `@`
  别名树之外）。apps/web 桥面改为从桥成员派生
  （`Parameters<Window['hermesDesktop']['notify']>[0]`）——零复制、随上游自动
  对齐；原 `import type ... from '@/global'` 会 TS2305。
- 静态核对：apps/web 对 vendor 的 69 处具名类型导入全部仍可解析（仅上述一处需改）；
  vendor/src 里 118 个 `hermesDesktop.*` 用法中除 `savePastedText` 外全部为可选成员
  （optional-chain 安全），无其它必填缺口。
